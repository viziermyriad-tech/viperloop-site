# AGENTS.md — VIPERLOOP

Инструкции для ИИ-агентов (и людей), работающих в этом репозитории.

## Проект

VIPERLOOP — неоновая 3D-змейка в стиле slither.io. Одностраничное PWA: вся игра в
`index.html` (~1100 строк, один IIFE), работает офлайн через service worker, открывается
с `file://` и с любого статического хостинга.

## Структура

- `index.html` — вся игра: Three.js-сцена, `class Snake`, боты, звук (WebAudio), PWA-регистрация
- `sw.js` — service worker: офлайн-кэш + автообновление. Константа `CACHE = "viperloop-v1"` —
  **обязательно повышать** версию при изменении игровых ресурсов
- `manifest.webmanifest` — манифест PWA. Все пути относительные
- `vendor/three.min.js` — Three.js r128, **не редактировать** (сторонний код)
- `icons/*.png` — иконки PWA, сгенерированы процедурно
- `tools/make-icons.js` — генератор иконок (чистый Node, без зависимостей): `node tools/make-icons.js`
- `README.md` — описание для людей

## Главные правила

1. **Не добавлять внешние зависимости и CDN.** Three.js уже локальный — PWA обязан работать офлайн.
2. **Только относительные пути** в `index.html`, `sw.js`, `manifest.webmanifest`. Сайт деплоится
   в подпапку (GitHub Pages: `/viperloop-site/`), а также в корень (локально). Абсолютные пути
   (`/index.html`, `https://site/…`) сломают PWA на одном из окружений.
3. Поменял `index.html` / `sw.js` / манифест / иконки → **bump `CACHE` в `sw.js`**
   (viperloop-v1 → viperloop-v2), иначе существующие инсталляции не получат обновление.
4. Иконки — не править руками, перегенерировать: `node tools/make-icons.js`.
   (В генераторе `hslToRgb` использует смещения `f(0), f(8), f(4)` — не «лечить» их «на глаз».)
5. Весь UI-текст — на русском.
6. Боты (`NAMES`) и палитра (`HUES`) меняются только в конфиге в начале скрипта `index.html`.

## Как проверять изменения

- Синтаксис игрового скрипта (последний `<script>` без `src` в `index.html`):
  ```bash
  node -e "const s=require('fs').readFileSync('index.html','utf8');const m=[...s.matchAll(/<script>([\s\S]*?)<\/script>/g)];new Function(m[m.length-1][1]);console.log('OK')"
  ```
- Локальный запуск: любой статический сервер, например `npx serve . -p 8080`.
  PWA-функции (service worker) работают только на `https` или `127.0.0.1/localhost`.
- Отладочные хуки в консоли браузера: `window.__debug()` — состояние игры
  (игрок, змейки, сферы, время), `window.__audio` — звуковой движок.

## Архитектура (что внутри index.html, один IIFE)

- **Конфиг** вверху скрипта: `A` (арена), `SPACING`, `TURN`, `STEER_RATE`, `HUES`, `NAMES`.
- **`class Snake`**: голова + сегменты по трассе, стиринг (`desired`/`angle`), буст
  (сжигает длину, падает сферы), `spawnT` — 2,5 с неуязвимости после спавна.
- **Боты**: охота на крупные сферы, уклонение от чужих голов, редкие спринты,
  респаун через 3,5 с; мёртвые чистятся `purgeDead()` каждый кадр (не удалять!).
- **Коллизии**: чужая голова и шея смертельны — проверка с сегмента **1**, не с 4.
- **Свободный полёт**: `findSpawn()` учитывает не только головы, но и **тела** всех змеек —
  в поздней игре одна гигантская змейка может заполнить арену, и простой spawn убивает игрока.
- **Звук** (`AudioFX`): генеративная музыка + SFX на WebAudio без файлов; инициализация
  только по жесту пользователя (обязательное требование браузеров); mute — `M` / кнопка 🔊.
- **Управление**: клавиатура (←/→ — поворот, ↑/W/пробел/ЛКМ — буст) + сенсорные зоны
  (левая/правая половина экрана — поворот, два пальца — буст). Источник выбирается сам
  (`isTouch`), наборы объединяются в `keys` через `syncKeys()` — не плодить отдельные флаги.
- **HUD**: лидерборд (топ-5), миникарта, статистика; имена игроков экранируются `esc()` —
  не вставлять `player.name` в `innerHTML` напрямую.

## Деплой

- `origin` — приватный `viziermyriad-tech/viperloop` (основной проект, код)
- `site` — публичный `viziermyriad-tech/viperloop-site` (копия для GitHub Pages,
  https://viziermyriad-tech.github.io/viperloop-site/). GitHub Pages для приватных репо на
  этом аккаунте недоступен — поэтому публичная копия.
- После изменений: `git push origin main && git push site main`.
- Игрокам с установленным PWA при обновлении сайта появится тост «Обновить»
  (механизм — `updatefound` + `SKIP_WAITING` в нижнем скрипте `index.html`).

## Известные грабли

- `requestAnimationFrame` **останавливается в фоновых вкладках** — в тестовых сценариях
  («игропет» не меняется в фоне) это норма, а не баг игры.
- `three.min.js` в `vendor/` — 600 КБ, в `git lfs` не кладём, коммитим обычным файлом.
- Service worker при смене версии старую копию не отключает до `SKIP_WAITING`/перезагрузки —
  это осознанно (игрок не теряет текущую игру в пользу старого кэша).
- 2D-прототип (`snake.html`) живёт в соседней папке разработки, **не в этом репо** —
  сюда его не копировать.
